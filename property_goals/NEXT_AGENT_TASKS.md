## Задача 1 — Проверить нормализацию адресов

В предыдущей сессии найден и исправлен критический баг: адреса лотов используют «корп 3»,
а срезы 2GIS пишут «к3» (без пробела). Фикс дал +627 матчей.

Нужно проверить: нет ли других паттернов несовпадения?

**Что проверить:**
- `стр` vs `строение` vs `стр N` (строения)
- `вл` vs `владение`
- `сооружение` vs `соор`
- Разные написания дробных номеров: `2/8` vs `2-8` vs `2 8`
- Разные написания корпуса с буквой: `к1а` vs `корп 1а`
- Любые другие systematic расхождения между lot `address_norm` и snapshot `address_norm`

**Как проверить:**
1. Взять лоты без матча — `df[df['match_confidence'].isna()]`
2. Для каждого лота: искать его address в срезах вручную/fuzzy — есть ли вообще такой адрес?
3. Сравнить форматы — где расходятся

**Где код:**
- `canon_addr()` в `match_gap_snapshots.py` (строки 144–159) — сюда добавлять новые правила
- Та же функция дублирована в `build_business_history.py` (добавить туда же)

## Задача 2 — Паттерн «выкуп действующим арендатором»

**Открытие из предыдущей сессии:**

Лот 18499876 (подвал, Верхняя Красносельская 8 к3) — победитель ООО «Креатив».
Аутпаб (паб-бильярдная, ООО «Ладомир», ОКВЭД 56.30) работает в этом подвале с 2008 года.
Бизнес присутствует во ВСЕХ срезах 2GIS — до и после продажи. Матч не находится,
потому что алгоритм ищет только НОВЫЕ бизнесы.

**Гипотеза:** существующий арендатор выкупает помещение, которое раньше арендовал у города.

**Что нужно сделать:**

1. **Проверить связь с «публичным предложением»:**
   - Фильтровать по `форма_проведения == 'Публичное предложение'` среди unmatched лотов
   - Публичное предложение — нисходящий аукцион, используется для неликвида или когда
     арендатор имеет право преимущественного выкупа. Возможно, доля «выкупа арендатором»
     выше среди публичных предложений.

2. **Написать детектор «стабильного бизнеса»:**
   - Логика: бизнес присутствует ≥ в 3 срезах ДО даты продажи лота И остаётся
     ≥ в 1 срезе ПОСЛЕ продажи → помечать как `match_time_window = "existing_tenant_buyout"`
   - Данные для этого есть в срезах `moscow/*.with_norm.csv`
   - Нужно смотреть по address_norm + расстояние ≤ 50м (более строгое чем 250м,
     чтобы не захватывать соседей по кварталу)

3. **Оценить масштаб:** сколько unmatched лотов попадают под этот паттерн?

## Задача 3 — Фильтр подходящих помещений для матчинга

**Проблема:**

Текущий алгоритм матчинга не учитывает соответствие типа бизнеса типу помещения.
Пример: подвал 126 м² не может быть занят «Красным и Белым» или аптекой федеральной сети —
у них есть требования к этажу и видимости.

**Что нужно сделать:**

1. **Изучить существующие данные о требованиях:**
   - `retailstreets_parser/data/retailstreets_requirements.csv` — уже используется в
     `revalidate_matches.py` для проверки площади
   - Проверить, есть ли там данные об этаже (подвал допустим/недопустим)

2. **Собрать правила по типам помещений:**
   - **Подвал:** не подходят сети с витринными требованиями (алкомаркеты федеральные,
     аптеки сетевые, продуктовые супермаркеты), подходят: ПВЗ, фитнес, бьюти, паб
   - **1-й этаж:** подходит большинство
   - **2-й этаж и выше:** не подходят форматы с высоким пешеходным трафиком

3. **Применить фильтр в двух местах:**
   - В `match_gap_snapshots.py` при оценке кандидатов — снижать confidence для
     неподходящих комбинаций (этаж × категория)
   - В `revalidate_matches.py` — добавить этаж как дополнительный критерий валидации

4. **Важно:** перед реализацией — **проверить данные**. Посмотреть реальное распределение
   матчей по этажу: какие сети реально заходят в подвалы по имеющимся данным?
   Не делать правила из головы — делать из данных.
