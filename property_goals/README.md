# Property Goals

Исторические данные по лотам `investmoscow`, которые реально были куплены, и попытка восстановить их пост-покупочное использование.

## Что лежит в папке

- `app.py` — Streamlit-приложение.
- `requirements.txt` — зависимости для деплоя.
- `investmoscow_sold_2022_2026.csv` — исходный экспорт купленных лотов.
- `investmoscow_sold_2022_2026_clean.csv` — очищенный CSV без лишних технических полей.
- `investmoscow_sold_2022_2026_clean.with_norm.csv` — тот же CSV с нормализованным адресом `address_norm`.
- `investmoscow_sold_2022_2026_enriched.csv` — лоты с первым matching по использованию.
- `investmoscow_sold_2022_2026_enriched_geo.csv` — финальный вариант после гео-проверки.
- `moscow/` — снапшоты справочника организаций Москвы по датам.
- `matches/` — промежуточные и итоговые результаты матчинга.

## Как отбирались лоты

В выборку попадают только реально купленные лоты:

- есть `итоговая_цена_руб`
- нет признака `Отказ победителя`

Срез по годам:

- `2022`: 737
- `2023`: 971
- `2024`: 870
- `2025`: 1065
- `2026`: 225

Всего: `3868` лотов.

## Логика матчинга

Цель была не найти покупателя по протоколу, а понять, что появилось на объекте после покупки:

- вероятное название компании
- вероятная категория использования

### Шаг 1. Нормализация адресов

Для лотов и для снапшотов `moscow` были нормализованы адреса:

- убраны `г. Москва`, округа и служебные префиксы
- приведены к единому виду `улица / дом / корпус / строение`
- отброшены этажи, помещения, подвалы и прочие внутренние хвосты

Результат:

- `investmoscow_sold_2022_2026_clean.with_norm.csv`
- `moscow/*.with_norm.csv`

### Шаг 2. Exact match по адресу

Для каждого лота строился первый строгий матч:

- по `address_norm`
- по ближайшему снапшоту после даты покупки

Это дало адресные совпадения, но на одном адресе часто оказывалось много компаний.

Промежуточные файлы:

- `matches/property_usage_best_match_exact.csv`
- `matches/property_usage_all_matches_exact.csv`

### Шаг 3. Before / after

Дальше матчинг был усилен сравнением снапшотов:

- `before` — ближайший снапшот до покупки
- `after` — ближайший снапшот после покупки
- в кандидаты брались только компании, которые появились в `after`, но отсутствовали в `before`

Это уже ближе к задаче "подо что купили".

Промежуточные файлы:

- `matches/property_usage_before_after_best.csv`
- `matches/property_usage_before_after_new_companies.csv`

### Шаг 4. High / medium

Из результата `before/after` были отдельно выделены более пригодные кейсы:

- `high`
- `medium`

Промежуточные файлы:

- `matches/property_usage_before_after_best_high_medium.csv`
- `matches/property_usage_top_candidates_high_medium.csv`
- `matches/property_usage_likely_summary.csv`

На этом этапе было `495` лотов с вероятным использованием.

### Шаг 5. Гео-проверка

После этого кандидаты были проверены по координатам:

- координаты лота: `latitude / longitude`
- координаты компании: `match_lat / match_lon`

Для каждого кандидата считалось расстояние в метрах и гео-качество:

- `0-30m`
- `30-100m`
- `100-250m`
- `250m+`

Файл проверки:

- `matches/property_usage_geo_verified.csv`

### Шаг 6. Гео-очистка

Финальная очистка была такой:

- `0-30m` и `30-100m` оставляем
- `100-250m` понижаем до `low`
- `250m+` исключаем

Итог после гео-фильтра:

- было `495` матчей
- осталось `460`
- удалено `35` плохих кейсов

Финальное распределение:

- `high`: `216`
- `medium`: `235`
- `low`: `9`

Финальные файлы:

- `matches/property_usage_likely_summary_geo.csv`
- `investmoscow_sold_2022_2026_enriched_geo.csv`

## Что использует приложение

`app.py` читает данные в таком порядке:

1. `investmoscow_sold_2022_2026_enriched_geo.csv`
2. `investmoscow_sold_2022_2026_enriched.csv`
3. `investmoscow_sold_2022_2026_clean.csv`

То есть приложение старается использовать максимально очищенный вариант, но не падает, если финальный enriched-файл отсутствует.

## Что показывает приложение

В интерфейсе доступны:

- карта купленных лотов
- фильтры по форме, году, округу, этажу, цене, площади и `Usage match`
- метрики по выборке
- scatter `участники ↔ превышение`
- таблица с колонками:
  - `Likely company`
  - `Likely usage`
  - `Usage match`

## Ограничения

- В справочнике `moscow` нет кадастрового номера, поэтому проверка шла не по кадастру, а по адресу, времени и координатам.
- На одном адресе может быть несколько компаний и несколько помещений.
- Поэтому `likely_company` и `likely_usage` — это вероятностная реконструкция пост-покупочного использования, а не юридически точное доказательство пользователя помещения.

```bash
streamlit run property_goals/app.py
```

## Текущий временной фильтр matching

Финальная витрина теперь использует только совпадения, где организация появилась в ближайшем `after`-снапшоте через `180-365` дней после даты покупки.

Это убирает дальние совпадения через несколько лет, которые технически совпадают по адресу, но плохо объясняют пост-покупочное использование помещения.

Дополнительно кандидат отбрасывается, если тот же `match_id` уже встречался в любом справочнике `moscow` до даты покупки. Это защищает от случаев, где организация существовала раньше, но адрес был записан в другом порядке, например `Парковая 3-я, 9` против `3-я Парковая улица, 9`.

Еще один защитный фильтр ищет похожее название организации в радиусе `100 м` в старых снапшотах до покупки. Это ловит случаи, когда `match_id` изменился, но бизнес, по сути, уже был рядом до продажи.

Текущий baseline итог после фильтра `180-365` дней:

- `90` matched lots
- `high`: `40`
- `medium`: `49`
- `low`: `1`

Файлы recent matching:

Почему матчей мало:

- Для лотов `2022-2023` ближайший доступный `after`-снапшот только `2025-09`, поэтому они почти все выпадают из окна `180-365` дней.
- Для лотов `2026` еще недостаточно времени, чтобы пройти нижнюю границу `180` дней.
- Начальный before/after matching строгий: кандидат должен появиться на том же нормализованном адресе, а затем пройти гео- и anti-preexisting-фильтры.
- Часть технически точных адресных совпадений удаляется, потому что организация существовала до покупки.

Файлы:

- `matches/property_usage_likely_summary_geo_time_filtered.csv` — audit-файл только с матчами в окне `180-365` дней.
- `matches/property_usage_likely_summary_geo.csv` — основной summary matching, тоже очищен до окна `180-365` дней.
- `matches/property_usage_likely_summary_geo_unfiltered.csv` — исходный geo-summary до временного фильтра, только для аудита.
- `investmoscow_sold_2022_2026_enriched_geo.csv` — финальный файл для приложения, уже очищенный от дальних совпадений.
