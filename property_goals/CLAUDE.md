# Property Goals — контекст для агента

## Цель проекта

Восстановить пост-покупочное использование коммерческих помещений, проданных на аукционах mos.ru (investmoscow.ru) в 2022–2026 годах. Данные о победителях аукционов закрыты — определяем, что появилось на объекте после покупки, по срезам справочника 2GIS.

Задача: к каждому из 3868 купленных лотов подобрать вероятную компанию-арендатора и категорию использования.

**Термин:** "срез" = снимок базы 2GIS на определённую дату (не говорим "снапшот").

### Срезы 2GIS (moscow/) — 21 срез

| Метка | Тип |
|-------|-----|
| `2020-04` … `2021-10` | Ранние срезы |
| `2022-01` … `2024-10` | Gap-срезы (покрывают исторический пробел) |
| `2025-05`, `2025-07`, `2025-09`, `2025-11` | Промежуточные |
| `2026-02`, `2026-03`, `2026-04` | Свежие срезы |

Исторический пробел 2021-10 → 2025-09 (~4 года) **закрыт** gap-срезами.

## Логика матчинга

- Лот продан → ищем бизнес, появившийся рядом (≤250м) в течение **до 1 года** после продажи
- Сравниваем пары срезов (prev → curr): бизнес есть в curr, но не было в prev → кандидат
- `MIN_AFTER_DAYS = 0`, `MAX_AFTER_DAYS = 365`, `MAX_DISTANCE_M = 250`
- Confidence: `high` (1 кандидат ≤30м), `medium` (≤3 кандидата ≤100м), `low` иначе
- Многолотовые здания: если несколько лотов на одном адресе — всем присваивается `multilot_building = "1"`, confidence не снижается
- В enriched CSV попадают только `high`/`medium` матчи

```python
("2022-08", "2022-12"), ("2022-12", "2023-12"), ("2023-12", "2024-05"),

("2026-03", "2026-04"),
```

При появлении нового среза (например, `2026-07`):
1. Добавить пару `("2026-04", "2026-07")` в `SNAPSHOT_PAIRS` в `match_gap_snapshots.py`
2. Обновить `LATEST_LABEL = "2026-07"` в `build_business_history.py`
3. Перезапустить полный pipeline

Синхронизированы между `match_gap_snapshots.py` и `build_business_history.py`.

- Терминалы оплаты, Платёжные терминалы

- Государственные дошкольные учреждения, Общеобразовательные школы
- Органы государственной власти, Многофункциональные центры, Библиотеки
- Аварийные / справочные / экстренные службы
- Жилищно-коммунальные, Правоохранительные органы
- Новостройки, Общественные / политические организации

**`IMPLAUSIBLE_NAME_SUBSTRINGS` (по имени):**
- банкомат, 5post, 5 post, qiwi, киви
- бери заряд, зарядная станция
- автомат по продаже кофе, кофейный автомат, автомат с , автомат копировальных

`revalidate_matches.py` дополнительно проверяет соответствие площади лота требованиям категории из `../retailstreets_parser/data/retailstreets_requirements.csv` (4× tolerance).

### Нормализация брендов

`BRAND_ALIASES` в обоих скриптах приводит варианты к единому имени:
Wildberries/вайлдберриз → "Wildberries", OZON/озон → "Ozon", CDEK/сдэк → "СДЭК" и т.д.

В `build_business_history.py`: для известных брендов (`KNOWN_BRANDS`) убирается суффикс рубрики — хранится просто "Wildberries", а не "Wildberries (Грузоперевозки)".

История дедуплицируется по имени бренда (key = canonical.lower()) — одна запись на компанию независимо от смены рубрик в 2GIS.

**Фикс 2026-05-06 #1:** 495 лотов переклассифицированы из `new_business` → `existing_tenant`.
Логика: `likely_company` присутствовал в срезе 2GIS с датой **до** `дата_подведения_итогов` на расстоянии ≤250м. Скрипт: `_fix_presale_reclassify.py`. Основная масса — срез 2021-10 (2GIS резко расширил базу в октябре 2021).

**Фикс 2026-05-06 #2:** 116 матчей очищены из-за несовместимой площади (`cleared_area_mismatch`).
Логика: площадь лота < 50% от минимума сети ИЛИ > 200% от максимума сети из `retailstreets_requirements.csv`. Скрипт: `_clear_area_mismatches.py`. Типичные случаи: Ozon (20-60м²) → лот 130-420м²; Wildberries (40-120м²) → лот 5м² или 260м².

**Фикс 2026-05-07 #1:** 14 матчей очищены из-за нарушения зоны 100м от образовательных/медицинских/торговых учреждений (`cleared_school_zone`).
Логика: `near_school_100m == 1` И `likely_company` — алкомаркет (Винлаб, Красное&Белое, Ароматный мир и др.). Основание: 171-ФЗ ст. 16. Скрипт: `_clear_school_matches.py`.
Датасет ограниченных зон расширен поэтапно:
- OSM: school/kindergarten/college/university/music_school (7465)
- Правительственный реестр Москвы data-2263-21-02-2026.csv (5204 зданий, в т.ч. 104 ДТДМ/ЦДТ/ДДТ)
- OSM медицинские: hospital/clinic/doctors (4015 объектов, 171-ФЗ ст.16)
- OSM рынки/АЗС/вокзалы: marketplace/fuel/railway_station без метро (1463 объекта, 171-ФЗ ст.16)
- Итого в schools_moscow.csv: **18 147 объектов**
- Лотов в зоне ограничения: 842 → 1037 (школы) → 1463 (+ медицина) → **1495** (+ рынки/АЗС/вокзалы)

**Фикс 2026-05-07 #3:** 3 матча очищены из-за площади лота < 50 м² при алкомаркете как основном кандидате (`cleared_area_mismatch`).
Основание: 171-ФЗ ст. 18 — для розничной торговли алкоголем в Москве минимальная площадь 50 м². Скрипт: `_clear_alco_min_area.py`.
Также: `ВИНЛАБ.area_min_m2` установлен в 50 (ранее отсутствовал) → убрано 127 рекомендаций для лотов < 50 м².

**Фикс 2026-05-07 #4:** 7 матчей очищены из-за отсутствия отдельного входа с улицы (`cleared_no_sep_entrance`).
Логика: `likely_company` — алкомаркет И `тип_входа` не содержит "отдельный". Основание: 171-ФЗ ст. 16 + СП 54.13330 (алкомаркет в жилом доме требует отдельного входа с улицы). Скрипт: `_clear_no_sep_entrance.py`.
Одновременно: `separate_entrance = True` добавлен всем 10 алкомаркетам в `retailstreets_requirements.csv`, что убрало ~3342 рекомендаций алкомаркетов для лотов без отдельного входа.

**Важно:** `existing_tenant` присваивается только лотам с непустой `история_бизнесов` — т.е. в 2GIS есть записи по адресу лота. Если истории нет, кандидат из `detect_tenant_buyout` — это сосед по кварталу, а не арендатор этого помещения. Проверка встроена в `merge_tenant_buyout.py`.

### Два типа матчей

| `match_confidence` | Значение |
|--------------------|----------|
| `high` / `medium` / `low` | Новый бизнес, появившийся после покупки (≤365 дней) |
| `existing_tenant` | Бизнес работал ≥3 срезов ДО продажи и остался ≥1 срез ПОСЛЕ — возможный выкуп арендатора |

## Колонки истории зданий

`build_business_history.py` добавляет три колонки в enriched CSV. Все три — pipe-separated списки, радиус 250м, 21 срез.

| Колонка | Содержимое |
|---------|-----------|
| `история_бизнесов` | Все уникальные бизнесы за все срезы |
| `сейчас_в_здании` | Бизнесы, присутствующие в `LATEST_LABEL` (2026-04) |
| `были_в_здании` | Были в каком-либо срезе, но отсутствуют в `LATEST_LABEL` |

**Важно:** это коммерческий контекст района (250м), а **не** история конкретного помещения. На одном адресе может быть много разных юнитов — неизвестно, какой из них занимал каждый бизнес.

## Приложение (app.py)

- Карта лотов с попапом: адрес, площадь, цена, дата торгов, арендатор, категория, дней до открытия; сейчас в здании; были в здании; история здания; предупреждение о многолотовом здании
- Фильтры в сайдбаре: форма проведения, качество совпадения, арендатор найден, год, округ, этаж, площадь, цена
- Таблица: арендатор, категория, сейчас/были в здании, история здания, рекомендуемые сети, цены, ссылка
- Аналитика: KPI (уникальные арендаторы, доля маркетплейсов, медиана открытия, доля 1-го этажа + подвал), топ компаний и категорий, 6 инсайт-карточек, матчи по годам

## Ключевые находки (из данных)

- **33% арендаторов — ПВЗ маркетплейсов** (Wildberries, Ozon, ЯМ), медиана площади ~93 м²
- **Публичное предложение** (нисходящий аукцион) закрывается на ~25% ниже старта; арендатора находят реже, чем у конкурентных торгов
- **~66% арендаторов — 1-й этаж, ~30% — подвал**; 2-й этаж и выше — единицы
- **Медиана открытия — 159 дней**, 23% бизнесов открываются за первые 3 месяца
- **Красота — второй кластер** (~70 адресов: барбершопы, ногтевые, косметологи)
- **Сетевой ретейл остаётся:** Пятёрочка 92%, Wildberries 91%, Винлаб 90% — открылись и не уходят
- **B2B уходит из улицы:** страхование, IT, полиграфия — исчезают из уличного ретейла

## Ограничения данных

- Нет кадастрового номера → матч по адресу + координатам, не по объекту
- На одном адресе может быть несколько помещений — неизвестно, какое именно занял бизнес
- `likely_company` и `likely_usage` — вероятностная реконструкция, не юридически точная
- `multilot_building = "1"` — флаг: несколько лотов на одном адресе
- История здания (250м) ≠ история конкретного помещения

## Retailstreets (рекомендации по сетям)

Для всех 3868 лотов рассчитаны подходящие торговые сети на основе площади и этажа.

- Источник: `matches/property_retailstreets_summary.csv` — колонки `rs_top_category`, `rs_top_chains`, `rs_chains_count`
- Генерация: `match_retailstreets.py`
- В `app.py`: в таблице и попапе карты для unmatched лотов

### Фильтр этажей в рекомендациях

`retailstreets_requirements.csv` содержит колонку `floor` — цепочки с явным требованием 1-го этажа не рекомендуются для подвальных лотов.

Вручную добавлены (2026-05-05, после проверки в 2GIS):
- **КРАСНОЕ И БЕЛОЕ** → `floor = первый этаж`
- **АРОМАТНЫЙ МИР** → `floor = первый этаж`

После изменений `match_retailstreets.py` надо перезапустить.
