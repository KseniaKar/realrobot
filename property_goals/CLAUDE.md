# Property Goals — контекст для агента

## Цель проекта

Восстановить пост-покупочное использование коммерческих помещений, проданных на аукционах mos.ru (investmoscow.ru) в 2022–2026 годах. Данные о победителях аукционов закрыты — определяем, что появилось на объекте после покупки, по срезам справочника 2GIS.

Задача: к каждому из 3868 купленных лотов подобрать вероятную компанию-арендатора и категорию использования.

**Термин:** "срез" = снимок базы 2GIS на определённую дату (не говорим "снапшот").

### Срезы 2GIS (moscow/)

Доступные срезы по хронологии:

| Метка | Тип |
|-------|-----|
| `2021-10` | Старый срез (до пробела) |
| `2022-01` … `2023-12` | Gap-срезы (плоские xlsx) |
| `2024-05`, `2024-09`, `2024-10` | Gap-срезы (по районам) |
| `2025-09`, `2025-11` | Промежуточные |
| `2026-02`, `2026-03`, `2026-04` | Свежие срезы |

Исторический пробел 2021-10 → 2025-09 (~4 года) **закрыт** gap-срезами.

## Логика матчинга

Единая логика для всех лотов:
- Лот продан → ищем бизнес, появившийся рядом (≤250м) в течение **до 1 года** после продажи
- Сравниваем пары срезов (prev → curr): бизнес есть в curr, но не было в prev → кандидат
- `MIN_AFTER_DAYS = 0` (нет минимума), `MAX_AFTER_DAYS = 365`, `MAX_DISTANCE_M = 250`
- Confidence: `high` (1 кандидат ≤30м), `medium` (≤3 кандидата ≤100м), `low` иначе
- Дедупликация зданий: если один бизнес — лучший кандидат для нескольких лотов одного здания → confidence → `low`
- В enriched CSV попадают только `high`/`medium` матчи

## Pipeline матчинга (текущий)

```
process_gap_snapshots.py       → разбор срезов в moscow/{label}.with_norm.csv
match_gap_snapshots.py         → основной матчинг по 13 парам срезов
merge_gap_matches.py           → слияние в enriched (идемпотентно, только high/medium)
revalidate_matches.py          → очистка невалидных кандидатов
```

Дополнительные источники (legacy, запускать не нужно при наличии gap-матчей):
```
rebuild_time_filtered_matches.py  → baseline 180-365d матчи
match_recent_2026_04.py           → recent матчи (0-180d, срез апрель 2026)
merge_recent_2026_04_matches.py   → слияние recent
recover_lost_matches.py           → first_after_snapshot (4-летнее окно, ненадёжно)
```


### Фильтры невалидных кандидатов

`IMPLAUSIBLE_SUBSTRINGS` (по рубрике): водоматы, постаматы, зарядки, справочные госслужбы, ЖКУ, новостройки, общественные организации.

`IMPLAUSIBLE_NAME_SUBSTRINGS` (по имени): eco-контейнеры, пункты сбора батареек.

`_ADDRESS_LIKE_RE` (по имени): названия вида "Романов переулок, 7" — адрес вместо имени.

`revalidate_matches.py` дополнительно проверяет соответствие площади лота требованиям категории из `../retailstreets_parser/data/retailstreets_requirements.csv` (4x tolerance).

## Приложение (app.py)

- Карта с попапом для каждого лота: адрес, площадь, цена, дата торгов, арендатор, категория, **дата торгов + "бизнес найден через X дн."**
- Фильтры: форма проведения, качество совпадения, **арендатор найден (Да/Нет/Все)**, год, округ, этаж, площадь, цена
- Таблица лотов с колонками: арендатор, категория, подходящие сети, цены, ссылка
- Инсайты: топ компаний-арендаторов, ключевые выводы, таблица покрытия по годам

## Ограничения данных

- Нет кадастрового номера → матч по адресу + координатам, не по объекту
- На одном адресе может быть несколько помещений — неизвестно, какое именно занял бизнес
- `likely_company` и `likely_usage` — вероятностная реконструкция, не юридически точная
- Для лотов с `first_after_snapshot_2025-09`: окно неопределённости ~4 года

## Retailstreets (рекомендации по сетям)

Для ВСЕХ 3868 лотов рассчитаны подходящие торговые сети на основе параметров помещения (площадь, этаж).

- Источник: `matches/property_retailstreets_summary.csv` — колонки `rs_top_category`, `rs_top_chains`, `rs_chains_count`
