# Property Goals — контекст для агента

## Цель проекта

Восстановить пост-покупочное использование коммерческих помещений, проданных на аукционах mos.ru (investmoscow.ru) в 2022–2026 годах. Данные о победителях аукционов закрыты — определяем, что появилось на объекте после покупки, по снапшотам справочника 2GIS.

Задача: к каждому из 3868 купленных лотов подобрать вероятную компанию-арендатора и категорию использования.

## Ключевые файлы

| Файл | Описание |
|------|----------|
| `investmoscow_sold_2022_2026_clean.with_norm.csv` | 3868 лотов с нормализованным адресом `address_norm` |
| `investmoscow_sold_2022_2026_enriched_geo.csv` | **основной выходной файл** — лоты с матчами |
| `moscow/` | Снапшоты 2GIS по датам: `2020-04`, `2021-10`, `2025-09`, `2026-01`, `2026-04` |
| `matches/` | Промежуточные и итоговые результаты матчинга |
| `app.py` | Streamlit-приложение, читает `enriched_geo.csv` |

### Снапшоты 2GIS

Критический факт: между `2021-10` и `2025-09` снапшотов нет (пробел ~4 года). Это означает:

- Лоты 2022–2024: ближайший `after`-снапшот — `2025-09` (~1000+ дней)
- Лоты 2025: `after`-снапшот — `2025-09` (до ~365 дней) или `2026-01`/`2026-04`
- Лоты с продажей после октября 2025: `after`-снапшот — `2026-04` (до 180 дней)

## Pipeline матчинга

Порядок выполнения скриптов строго задан:

```
rebuild_time_filtered_matches.py   → baseline enriched (окно 180-365d)
revalidate_matches.py              → очистка невалидных кандидатов
process_2026_04_snapshot.py        → разбор снапшота апрель 2026
match_recent_2026_04.py            → recent кандидаты (0-180d)
merge_recent_2026_04_matches.py    → слияние recent в enriched (идемпотентно)
recover_lost_matches.py            → восстановление лотов 2022-2024
```

### Логика каждого шага

**`rebuild_time_filtered_matches.py`**
- Берёт `property_usage_before_after_best.csv` — before/after сравнение снапшотов
- Оставляет компании, которых не было в `before` и которые появились в `after`
- Окно: `180-365` дней после покупки
- Защита от ложных совпадений: фильтр по `match_id` и схожести имени в 100м
- Выход: `investmoscow_sold_2022_2026_enriched_geo.csv`

**`revalidate_matches.py`**
- Удаляет кандидатов, которые не могут быть арендаторами:
  - `IMPLAUSIBLE_SUBSTRINGS`: водоматы, постаматы, зарядки, справочные госслужбы, ЖКУ, новостройки, общественные организации
  - `IMPLAUSIBLE_NAME_SUBSTRINGS`: eco-контейнеры ("контейнер для сбора"), пункты сбора отходов, пункты приёма батареек — проверяется по имени компании, не рубрике
  - Проверка площади: лот ↔ требования из `../retailstreets_parser/data/retailstreets_requirements.csv` (4x tolerance)
- Обрабатывает ВСЕ matched-лоты, включая `first_after_snapshot` и recent
- При полной очистке лота — обнуляет также `match_time_window` и `match_after_days` (иначе ghost-строки попадают в UI)
- Отчёт: `matches/revalidation_report.csv`

**`process_2026_04_snapshot.py`**
- Разбирает снапшот 2GIS апрель 2026
- Выявляет организации, которых не было в `2026-01` (новые за 3 месяца)
- Выход: `matches/moscow_2026_04_new_organizations.csv`

**`match_recent_2026_04.py`**
- Лоты, проданные не позднее 180 дней до `2026-04-30`
- Матчит по нормализованному адресу + расстоянию ≤ 250м
- Применяет `IMPLAUSIBLE_SUBSTRINGS` + `IMPLAUSIBLE_NAME_SUBSTRINGS` фильтр
- **Дедупликация зданий**: если один `match_id` является лучшим кандидатом для нескольких лотов одного здания → confidence понижается до `low` (несколько помещений в здании не могут все стать одной компанией)
- Confidence: `high` (1 кандидат, 0-30м), `medium` (≤3 кандидата, 0-100м), `low` иначе
- Выход: `matches/property_usage_recent_2026_04_summary.csv`

**`merge_recent_2026_04_matches.py`**
- Добавляет только `high`/`medium` recent-матчи в enriched
- **Идемпотентен**: перед записью сбрасывает старые recent-матчи (`match_time_window == "0-180d_recent_2026-04"`)
- Не трогает baseline и recovered матчи

**`recover_lost_matches.py`**
- Лоты 2022–2024, не матчившиеся из-за пробела в снапшотах
- Принимает первый доступный `after`-снапшот без ограничения `MAX_AFTER_DAYS`
- Те же `IMPLAUSIBLE_SUBSTRINGS` + `IMPLAUSIBLE_NAME_SUBSTRINGS` + площадной фильтр
- `high` confidence понижается до `medium` при `after_days > 365`
- Лейбл: `match_time_window = "first_after_snapshot_2025-09"`
- Отчёт: `matches/recovered_matches_report.csv`

## Текущее состояние матчинга (апрель 2026)

| Источник | Лотов |
|----------|-------|
| Baseline `180-365d` | ~56 |
| Recent `0-180d_2026-04` | ~35 |
| First snapshot `2025-09` | ~219 |
| **Итого** | **313** |

Из 3868 лотов матч имеют **313 (8.1%)** после реvalidации с `IMPLAUSIBLE_NAME_SUBSTRINGS`.

## Ограничения данных

- Нет кадастрового номера → матч по адресу + координатам, не по объекту
- На одном адресе может быть несколько помещений — неизвестно, какое именно занял бизнес. Обнаруживается как `low` confidence при дедупликации зданий
- Окно неопределённости для 2022–2023: ~4 года (снапшоты 2021-10 → 2025-09)
- `likely_company` и `likely_usage` — вероятностная реконструкция, не юридически точная

## Потенциальные улучшения

1. **Снапшоты 2022–2024** — добавить данные 2GIS за этот период, сократить окно неопределённости с 4 лет до 1 года
2. **Обновление recent** — при появлении снапшота `2026-07` перезапустить:
   ```
   py process_2026_07_snapshot.py   # новый скрипт по образцу process_2026_04_snapshot.py
   py match_recent_2026_07.py
   py merge_recent_2026_07_matches.py
   ```

## Retailstreets (рекомендации по сетям)

Для ВСЕХ 3868 лотов рассчитаны подходящие торговые сети на основе параметров помещения (площадь, этаж).

- Источник: `matches/property_retailstreets_summary.csv` — колонки `rs_top_category`, `rs_top_chains`, `rs_chains_count`
- Генерация: `match_retailstreets.py`
- В `app.py`: загружается в `load_data()` через merge по `номер_лота`, отображается в таблице («Подходящая категория», «Подходящие сети») и в popup карты для unmatched лотов

## Запуск приложения

```bash
streamlit run property_goals/app.py
```
