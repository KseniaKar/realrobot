# Техническое задание на создание системы парсинга investmoscow.ru

## Описание задачи

Создать парсер для сбора данных о продаже нежилых помещений с сайта Инвестиционный портал Москвы: https://investmoscow.ru/tenders/

### Фильтры для парсинга:
- Тип объекта: Нежилое помещение
- Действие: Купить (продажа)
- Статус: Прием заявок

---

## Целевые данные (поля)

| Поле | Тип | Пример |
|------|-----|--------|
| `url` | string | `https://investmoscow.ru/tenders/tender/19969959` |
| `площадь м²` | string | `14,3` (запятая как десятичный разделитель) |
| `цена руб.` | string | `2 885 000,00` (пробелы как разделители тысяч, запятая для копеек) |
| `адрес` | string | `ЮЗАО, Гагаринский р-н, ул. Косыгина, д. 5` |
| `функциональное_назначение` | string | `Свободное` |
| `тип_входа` | string | `Вход через иную собственность` |
| `этаж` | string | `1` или `Подвал` или `Цоколь` |
| `этажность` | string | `10` (целое число) |
| `метро` | string | `Аэропорт (11 мин)` |

---

## Технические требования

### Стек технологий:
- Python 3.9+
- Playwright (для браузера)
- requests (для API запросов)
- csv (для экспорта)

### Необходимые библиотеки:
```bash
pip install playwright requests
playwright install chromium
```

### Требования к коду:
1. Headless режим для автоматизации
2. User-Agent должен быть реалистичным
3. Задержки между запросами (0.3-0.5 сек)
4. Обработка ошибок с логированием
5. Сохранение прогресса (на случай обрыва)
6. Избегание дублирования — не парсить уже распарсенные URL

## Формат вывода

**Файл:** `data/investmoscow_YYYY-MM-DD.csv` (с текущей датой)

**Кодировка:** UTF-8-sig (для корректного открытия в Excel)

**Разделитель:** запятая

**Пример:**
```csv
url,площадь м²,цена руб.,адрес,функциональное_назначение,тип_входа,этаж,этажность,метро
https://investmoscow.ru/tenders/tender/19969959,14,3,"2 885 000,00","ЮЗАО, Гагаринский р-н, ул. Косыгина, д. 5",Свободное,Вход через иную собственность,1,10,Аэропорт (11 мин)
```

## Алгоритм работы

### Шаг 1: Получение данных через API
```python

params = {

    "pageSize": 100,
    "objectKinds": ["nsi:tender_type_portal:13"],
    "objectTypes": ["nsi:41:30011569"],
    "tenderStatus": "nsi:tender_status_tender_filter:1"
}

# API возвращает entities, внутри которых tenders
# Извлекать данные из каждого tender
```

### Шаг 2: Извлечение данных из API
```python
# Для каждого tender извлечь:
# - id (для URL)
# - objectArea (площадь)
# - startPrice (цена)
# - objectAddress (адрес)
# - objectTypeName (тип объекта)
# - additionalParams (этаж, тип входа)
# - functionalityPurposes (функциональное назначение)
# - subwayStations (метро)
# - floors (этажность)
```

### Шаг 3: Форматирование данных
```python
# Площадь: float -> строка с запятой (14.3 -> "14,3")
# Цена: int -> строка с пробелами и копейками (2885000 -> "2 885 000,00")
# Этажность: int -> строка (10 -> "10")
# Этаж: оставить как строку ("1", "Подвал", "Цоколь")
```

### Шаг 4: Экспорт в CSV
```python

# Записать заголовок с полями

```

## Известные проблемы и решения

| Проблема | Решение |
|----------|---------|
| API возвращает entities, а не tenders | Извлекать tenders из каждого entity |
| Этаж и этажность — разные поля | Этаж = где помещение, Этажность = сколько этажей в здании |
| CSV битая кодировка | Использовать encoding='utf-8-sig' |
| Потеря данных при обрыве | Сохранять прогресс каждые 20 объявлений в data/progress.json |
| Дубликаты URL | Использовать множество (set) для хранения URL |

---

## Критерии приёмки

1. Количество: Минимум 300+ объявлений
2. Полнота полей: Все поля заполнены на ≥80%
3. Корректность данных:
   - Площадь > 0
   - Цена > 0
   - Адрес содержит "АО," или "р-н" или "ул."
   - Этаж ≠ Этажность (это разные поля!)
4. Формат: CSV открывается в Excel без искажений кириллицы
5. Отсутствие дубликатов: Уникальные URL
6. Имя файла: `investmoscow_YYYY-MM-DD.csv`
